### 2.2 Security Fixes
- **Pessimistic locking** on transfers: add `@Lock(LockModeType.PESSIMISTIC_WRITE)` to CardRepository `findById` for transfer
- **Deterministic lock order**: lock cards by ID (lower first) to prevent deadlock
- **@Version** on Card entity for optimistic locking
- **CORS configuration**: add proper CORS config in SecurityConfig
- **No transfer endpoint for ADMIN**: remove transfer from admin scope
- **No direct balance modification**: ensure no endpoint allows direct balance changes

### 2.3 Missing Security Checks
- Add `AccessDeniedException` handler → 403 (not 500)
- Verify USER cannot access other USER's cards via URL manipulation

## Stage 3: DB Schema & JPA

### 3.1 Issues Found
- **No @Version on Card** — add for optimistic locking
- **N+1 risk**: `Card.person` is `FetchType.LAZY` but `CardMapper.toCardResponse` accesses `card.getPerson()` — need `@EntityGraph` on repository queries
- **Missing indexes**: add index on `card.person_id`, `card.card_status`, `card.expiration_date`

### 3.2 Fixes
- Add `@Version Long version` to Card entity
- Add Liquibase migration for `version` column and indexes
- Ensure `@EntityGraph` on all Card repository queries that need person data
